### نبذة عن المشروع

فاحص APK (APK Inspector) هو إضافة مرافقة لمدير ملفات AutoJs6. انقر على ملف APK أو APKS أو XAPK أو APKM أو APKZ أو AAB في مدير الملفات ليفتح تقرير فحص فورًا: اسم التطبيق، وإصداره، والأذونات التي يطلبها، وإمكانية تثبيته على هذا الجهاز، كل ذلك في شاشة واحدة. لا تُثبَّت الحزمة أبدًا، ولا يُعدَّل الملف الأصلي إطلاقًا.

يتكون التقرير من أربعة أقسام: «تفاصيل الحزمة» يعرض اسم التطبيق والأيقونة واسم الحزمة والإصدار ونطاق SDK والتحقق من التوقيع وسلسلة تدوير شهادات التوقيع وحجم الملف وبصمة SHA-256؛ و«المكونات» يسرد كل ملفات APK المقسمة وموارد OBB داخل الحزمة مع تمييز الأجزاء المطابقة لهذا الجهاز (وبالنسبة لملفات AAB تُسرد الوحدات)، ويجمع activity/الأسماء المستعارة وservice وreceiver وprovider المعلنة في manifest حسب العدد وحالة exported الصريحة، ويلخص مكتبات .so الأصلية حسب ABI والحجم غير المضغوط ومدى مطابقة الجهاز، ويسرد ملفات classes*.dex القياسية وأحجامها غير المضغوطة؛ و«الأذونات المطلوبة» يجمع أذونات النظام حسب مستوى الحماية ويبرز أذونات وقت التشغيل الخطرة أولًا مع شرح موجز؛ و«نتائج الأمان والتوافق» يلخص المشكلات البنيوية وحكم التوافق مع الجهاز. كما يفتح زر «عرض manifest» ملف AndroidManifest كاملًا بصيغة منسقة.

### أبرز الميزات

- تحسين تدريجي لمربع حوار المضيف: في إصدار متوافق من AutoJs6 يحتفظ مربع معلومات APK الحالي بكل حقوله الأصلية وإجراءات التثبيت/البيان، ثم يضيف ملخص فحص محليًا محدودًا ومرتبطًا بـ SHA-256؛ وعند غياب الإضافة أو تعطيلها أو قدمها أو عدم توافقها أو فشلها يبقى مربع الحوار الأساسي دون تغيير.
- تخطيط للنص الكبير والشاشات الضيقة: عند مقياس خط 1.5x/2.0x يُرتب رأس التقرير عموديًا عند ضيق المساحة، وتبقى عناوين شريط الأدوات المختصرة ظاهرة بالكامل، وتلتف قيم SHA-256 وأسماء الأذونات الطويلة بلا حذف، ويمنع بحث البيان في الوضع الأفقي واجهة الاستخراج بملء الشاشة للوحة المفاتيح.
- المظهر التكيفي: تتبع صفحة التقرير وعارض البيان إعداد النظام للوضع الفاتح/الداكن؛ وفي Android 12 والإصدارات الأحدث تستمد Material You لوحة الألوان من الخلفية، مع ألوان دلالية وأيقونات أشرطة نظام تراعي التباين وتحافظ على وضوح الصفحتين.
- بيانات الحاوية الوصفية: تقرأ بيانات SAI APKS وXAPK وAPKMirror APKM ضمن حد 1 MiB، وتعرض أداة الحزم/إصدار التنسيق وإصدار التطبيق المعلن وإدخال أيقونة موجودًا من دون استبدال حقائق manifest في APK.
- فحص بنقرة واحدة: يفتح التقرير مباشرة من مدير ملفات AutoJs6، دون تثبيت أو فك ضغط أو اتصال بالشبكة.
- ستة تنسيقات: APK القياسي، وتنسيقات الحزم متعددة الأجزاء (APKS وXAPK وAPKM وAPKZ)، وتنسيق التوزيع للمتاجر AAB؛ ويدعم APKS تصديري bundletool وSAI معًا.
- الإصدار والتوافق: يعرض اسم الحزمة واسم الإصدار ورمزه وحدود SDK الدنيا والمستهدفة والقصوى، مقارنةً بإصدار Android على الجهاز قبل التثبيت.
- شفافية الأذونات: تُجمع الأذونات المطلوبة حسب مستوى الحماية (وقت التشغيل/خطرة، التوقيع/محمية، عادية)، وتُبرز أذونات وقت التشغيل أولًا مع شرح من سطر واحد؛ وتظل المستويات غير المتاحة ظاهرة وموسومة بوضوح.
- تحليل الأجزاء المقسمة: يسرد كل مدخلات APK وموارد OBB في الحزمة ويميز الأجزاء المختارة لهذا الجهاز (الأساس، اللغة، كثافة الشاشة، بنية المعالج).
- محاكاة إعداد الجهاز: بدّل اللغة وكثافة الشاشة وABI داخل تقرير الحزمة؛ تعيد الإضافة تشغيل المحدد المحدود نفسه محليًا على اللقطة الخاصة وتعرض ملفات APK المضافة أو المزالة مقارنة بالجهاز الفعلي.
- تهيئة AAB وتسليمها: يفك ترميز إعدادات BundleConfig.pb بشكل محدود، ويعلّم وحدات base وfeature وasset وML وAI وSDK ببيانات التسليم وقت التثبيت والمشروط وعند الطلب وfast-follow والدمج والقابلية للإزالة؛ ولا تؤثر التهيئة أو manifest التالف أو المتجاوز للحد إلا في تعليقه الخاص.
- مسار احتياطي لهوية التطبيق عبر الموارد: عندما يتعذر على Android تحميل AAB أو حزمة تتجاوز الحد مباشرة، تُحل تسمية التطبيق وأيقونة نقطية للغة الجهاز وكثافته من resources.pb في AAB أو resources.arsc في APK من دون استخراج APK المتداخل كاملًا.
- كشف مكونات manifest: يحصي activity/الأسماء المستعارة وservice وbroadcast receiver وcontent provider عبر أجزاء APK المختارة أو وحدات AAB المفحوصة، ويجمع قيم android:exported الصريحة إلى مُصدَّر أو غير مُصدَّر أو غير محدد/غير محلول.
- نظرة عامة على المكتبات الأصلية: تجمع ملفات .so من أجزاء APK المختارة أو وحدات AAB حسب ABI والحجم غير المضغوط، وتحدد ABI المفضل للجهاز والبدائل المدعومة والبنى غير المدعومة من دون استخراج محتوى المكتبات.
- نظرة عامة على DEX: تسرد ملفات classes*.dex القياسية بترتيب طبيعي من أجزاء APK المختارة أو وحدات AAB مع الحجم غير المضغوط لكل ملف والإجمالي، من دون استخراج محتوى DEX أو فك ترميزه أو تفكيكه.
- إعادة استخدام التقرير: اضغط مطولًا على أي صف رئيسي في تفاصيل الحزمة لنسخ قيمته المجردة، أو شارك التقرير المطابق للشاشة بصيغة `text/plain` عبر لوحة المشاركة في Android؛ يبقى النص في الذاكرة ولا يُنشأ ملف أو يُطلب إذن تخزين.
- التحقق من التوقيع والشهادات: يتحقق تشفيريًا من توقيعات APK بنظم V2 وV3 وV3.1، ويبلغ عن وجود V1، ويعرض شهادات التوقيع الحالية وسلسلة التدوير المتحقق منها مع أدوار القديم/الجديد وبصمات SHA-256.
- التحقق من الملف الجانبي V4/V4.1: يشتق AutoJs6 فقط الملف المجاور المطابق `<اسم APK>.idsig` ويمنح واصفًا محدودًا للقراءة فقط؛ وتتحقق الإضافة من البيانات الموقعة والشهادة والمفتاح العام وملخص APK المقابل من V2/V3 وجذر fs-verity وشجرة Merkle المضمنة وأي موقّع تدوير V3.1.
- ملفات manifest مقروءة: تُفك ملفات manifest الثنائية في APK وملفات protobuf في AAB إلى XML داخل عارض مستقل للقراءة فقط، مع أرقام الأسطر وتلوين دلالي للبنية وبحث محدود لا يراعي حالة الأحرف، وإبراز النتائج والتنقل إلى السابقة أو التالية.
- إتاحة TalkBack وRTL: تُعرَّف أقسام التقرير كعناوين، ولكل إجراء ذي أيقونة تسمية منطوقة، وتوفر الصفوف التفاعلية المخصصة أهداف لمس بحجم 48 dp، وتُعلن النتائج الديناميكية، وتعكس الواجهة العربية التخطيط وفق اتجاه اللغة.
- التحقق من السلامة: تُحسب بصمة SHA-256 أثناء قراءة الملف، جاهزة للمقارنة مع البصمات المنشورة رسميًا.
- فحص بنيوي: يكتشف غياب حزمة الأساس، وتكرار الأجزاء أو نقص تبعياتها، وتعارض الإصدارات أو أسماء الحزم، ويميز كل نتيجة بين مانعة [!] وإرشادية [i].

### طريقة الاستخدام

1. نزّل فاحص APK وثبّته، ثم فعّله من مركز الإضافات في AutoJs6 (يتطلب AutoJs6 برمز إصدار 5277 أو أحدث).
2. افتح مدير ملفات AutoJs6 وحدد ملف الحزمة الذي تريد فحصه (APK أو APKS أو XAPK أو APKM أو APKZ أو AAB).
3. انقر على الملف، أو اختر «فحص حزمة Android» من قائمته؛ يظهر تقرير الفحص بعد لحظات.
4. اقرأ التقرير من الأعلى إلى الأسفل: أيقونة التطبيق واسمه، وتفاصيل الحزمة، والمكونات، والأذونات المطلوبة، ونتائج الأمان والتوافق.
5. في تقارير APKS وXAPK وAPKM وAPKZ، اختر اللغة وكثافة الشاشة وABI ثم طبّق المحاكاة لمقارنة ملفات APK المحددة بالجهاز الفعلي.
6. اضغط مطولًا على صف في «تفاصيل الحزمة» لنسخ قيمته، أو انقر «مشاركة التقرير» في شريط الأدوات لإرسال النص المطابق للشاشة عبر لوحة المشاركة في Android.
7. انقر على «عرض manifest» لقراءة AndroidManifest كاملًا، ثم اضغط زر الرجوع للعودة إلى مدير الملفات.

> يمكن للتطبيقات الأخرى أيضًا تمرير حزمة إلى فاحص APK عبر «فتح باستخدام» (ACTION_VIEW) في النظام، بشرط استخدام عنوان content مع نوع MIME مخصص لحزم Android. تعمل الإضافة في وضع القراءة فقط دائمًا ولا توفر أي منفذ للتثبيت.

### التنسيقات المدعومة

يتطابق الإجراء الرئيسي في مدير الملفات تطابقًا تامًا مع الامتدادات التالية (دون تمييز حالة الأحرف):

```text
APK, APKS, XAPK, APKM, APKZ, AAB
```

تنسيقات APKS وXAPK وAPKM وAPKZ حاويات تضم عدة ملفات APK مقسمة؛ أما AAB فهو تنسيق App Bundle المُقدَّم إلى متاجر التطبيقات: يمكن فحصه هنا، لكن تثبيته يستلزم تحويله أولًا بأداة مثل bundletool.

### الأسئلة الشائعة

#### هل يمكن لهذه الإضافة تثبيت ملفات APK؟

لا، وهذا تصميم مقصود. لا تطلب الإضافة إذن التثبيت ولا يوجد أي زر تثبيت في واجهتها؛ فمهمتها أن تريك محتوى الحزمة قبل تثبيتها. يبقى التثبيت من اختصاص مثبّت النظام أو مسار المضيف نفسه.

#### لماذا يتعذر فحص بعض الملفات؟

الأسباب الشائعة: تجاوز الملف حد 8 GiB؛ أو نقص مساحة التخزين المؤقت على الجهاز (يجب أن يبقى 128 MiB على الأقل حرًا)؛ أو تجاوز الحزمة حدود التحليل في عدد المدخلات أو حجمها؛ أو تعديل تطبيق آخر للملف أثناء قراءته؛ أو تلف بنية الملف نفسه. وتوضح رسالة الخطأ السبب المحدد.

#### هل يثبت كشف التوقيع أن الحزمة آمنة؟

لا. تتحقق الإضافة تشفيريًا من سلامة الحزمة وإثباتات الموقّع لنظم V2 وV3 وV3.1 وV4 وV4.1، وتعرض بصمات الشهادات وسلسلة التدوير؛ لكن التوقيع الصحيح يثبت فقط أن الحزمة لم تتغير منذ توقيعها، ولا يثبت موثوقية الموقّع أو التطبيق. قارن البصمة وSHA-256 بمصدر رسمي.

#### لماذا تظهر لملفات AAB رسالة «تتطلب تحويلًا قبل التثبيت»؟

تنسيق AAB مخصص للتوزيع عبر متاجر التطبيقات؛ ولا تستطيع أجهزة Android تثبيته مباشرة. تفك الإضافة manifest بصيغة protobuf وبنية الوحدات، وتستخدم resources.pb لحل اسم التطبيق المحلي وأيقونة نقطية ملائمة للكثافة للعرض، لكن التثبيت يظل يتطلب تحويله أولًا إلى APK(S) بأداة مثل bundletool.

### الأذونات والأمان

لا تطلب الإضافة أذونات التخزين أو الشبكة أو تثبيت الحزم. ولا تصل إلى الحزمة المحددة إلا عبر عنوان content مؤقت للقراءة فقط يمنحه المضيف؛ أما `.idsig` الاختياري فلا يتاح إلا عبر واصف مضيف محدود للاسم المجاور المطابق `<اسم APK>.idsig`، من دون تعداد المجلد أو مسارات مجاورة عشوائية. قبل الفحص تُنسخ المدخلات إلى لقطات للقراءة فقط في ذاكرة التطبيق الخاصة (ويُحسب SHA-256 أثناء نسخ الحزمة)، ويجري كل التحليل على اللقطات؛ حد `.idsig` هو 40 MiB وتُنظف اللقطات المنتهية خلال 24 ساعة. تُدقّق طلبات مدير الملفات حقلًا حقلًا، بما في ذلك إصدار البروتوكول ومعرّفا الطلب والإجراء وبيانات الهدف وإصدار المضيف وبنية URI والاسم والحجم ومنح القراءة فقط وBinder الجلسة. ولا تُقبل طلبات «فتح باستخدام» إلا بأنواع MIME المخصصة للحزم؛ وتُرفض application/zip وapplication/octet-stream ومنح الكتابة أو المنح الدائمة أو منح البادئة.

لمنع الملفات المصممة بخبث من استنزاف موارد الجهاز، يخضع التحليل للحدود التالية، وتُرفض الملفات المتجاوزة مع رسالة توضيحية:

- الحد الأقصى للملف الواحد 8 GiB، ويجب أن يبقى 128 MiB على الأقل من مساحة التخزين المؤقت حرًا أثناء النسخ، ويعالج كل إجراء ملفًا هدفًا واحدًا فقط.
- يُحلَّل 262144 مدخلًا كحد أقصى في الأرشيف، ويُفحص 4096 مدخل APK كحد أقصى في الحزمة، ولا يتجاوز اسم المدخل 4096 حرفًا.
- لا يتجاوز الحجم المعلن للمدخل الواحد 8 GiB، ولا يتجاوز الإجمالي المعلن 64 GiB.
- يقتصر فحص manifest في ملفات APK المتداخلة على 16 GiB، والبيانات الوصفية للحزمة على 4 MiB، وملف APK المؤقت لتحميل الأيقونة والاسم على 8 GiB.
- يقتصر BundleConfig.pb في AAB على 4 MiB. تشترك تعليقات التسليم في فحص AAB البالغ 512 ملف manifest / 64 MiB وتحتفظ بحد أقصى 128 قيمة شرط لكل وحدة؛ وتبقى الحدود والبيانات التالفة معزولة وموسومة.
- يقرأ المسار الاحتياطي للموارد بحد أقصى 64 MiB لكل جدول و8 MiB لكل أيقونة، مع ميزانية مشتركة قدرها 16 GiB للعثور على الجدول والأيقونة داخل APK متداخل؛ ولا يؤدي تجاوز الحد أو تلف المورد أو تعذر حل المرجع إلا إلى تعطيل ذلك المسار مع وسم واضح.
- يفحص تصنيف الأذونات 2048 طلبًا بحد أقصى، ويعرض 512 اسمًا آمنًا وفريدًا، ويقصر كل شرح محمّل على 240 حرفًا؛ وتُوسم العناصر المحذوفة ومستويات الحماية غير المتاحة بوضوح.
- تفحص إحصاءات المكونات 4096 إعلانًا بحد أقصى لكل manifest، و512 من manifests وحدات AAB بميزانية إدخال مشتركة قدرها 64 MiB؛ وتُوسم العناصر المحذوفة وقيم exported غير المحلولة وإخفاقات كل manifest بوضوح.
- تحتفظ إحصاءات المكتبات الأصلية بحد أقصى 32768 من مدخلات .so وتعرض 64 من أدلة ABI. تُقرأ حتى 4096 حزم APK متداخلة مختارة ضمن ميزانية مشتركة 16 GiB مع الاحتفاظ بما لا يزيد على 32 MiB من الدليل المركزي لكل APK؛ وتنتج الحدود والإخفاقات نتائج جزئية موسومة بوضوح.
- تحصي إحصاءات DEX كل المدخلات القياسية التي تم فحصها، لكنها تعرض بحد أقصى 128 مسارًا مرتبًا طبيعيًا؛ وهي تشارك المرور المحدود نفسه في الدليل المركزي مع نظرة المكتبات الأصلية، لذلك لا يُستخرج محتوى DEX ولا يُفك ترميزه أو يُفكك.

### واجهة الإضافة

يكتشف المضيف (AutoJs6) الإضافة ويستدعيها عبر المعرفات التالية، وهي مذكورة هنا لمطوري الإضافات والمضيفين:

```text
service action: org.autojs.plugin.EXPLORER_ACTION
execute action: org.autojs.plugin.EXPLORER_ACTION_EXECUTE
plugin id: apk-inspector
engine: explorer-action
variant: default
Explorer action id: inspect-android-package
host file information capability: v1
MIME type: Explorer: extension-only; ACTION_VIEW: dedicated Android package MIME types
required host build: 5277
```

الإصدار الحالي يجري فحصًا للقراءة فقط: لا زر تثبيت ولا إذن تثبيت ولا مثبّت حزم، ولا يُعدَّل الملف الأصلي، ولا تُعدَّد المجلدات. يستخدم V4 فقط مرشح `.idsig` المطابق الذي اشتقه المضيف، وينسخ واصفه المحدود للقراءة فقط إلى لقطة خاصة ثم يغلق جلسة المضيف فورًا. وعلى المضيفات المتوافقة يمكن لإمكانية معلومات ملفات المضيف v1 إلحاق ملخص محلي محدود ومرتبط ببصمة SHA-256 للمصدر المفحوص بمربع معلومات APK الحالي، مع بقاء تقرير Activity الكامل متاحًا. وإذا كانت الإضافة غائبة أو معطلة أو قديمة أو غير متوافقة أو فشل الفحص، يبقى مربع الحوار الأساسي كما هو ويستخدم المضيف مساره الاحتياطي المعتاد بصمت.

### البناء

```powershell
.\gradlew.bat :app:assembleDebug
```

بناء Release:

```powershell
.\gradlew.bat :app:assembleRelease
.\gradlew.bat :app:prepareReleaseArtifacts
.\gradlew.bat :app:verifyReleaseArtifacts
```

تُضبط معاملات البناء والتوقيع في version.properties وsign.properties؛ والحد الأدنى الحالي هو Android 7.0 (SDK 24) مع SDK مستهدف 36.

تُنشئ `prepareReleaseArtifacts` ملفات APK للإصدار وتنسخها إلى releases/ مع الإبقاء على قاعدة الاسم `autojs6-plugin-apk-inspector-v<version>-<CRC32>.apk`، ثم تكتب ملف `.sha256` مرافقاً لكل APK وملف `SHA256SUMS` مرتباً؛ وتتحقق `verifyReleaseArtifacts` بشكل مستقل من CRC32 في الاسم وSHA-256 الفعلي والملفات المرافقة والقائمة الإجمالية.

تُولَّد ملفات README وCHANGELOG بواسطة .python/generate_markdown.py من مصادر JSON والقوالب في .readme/ و.changelog/ (بعشر لغات). لتعديل الوثائق، حرر مصادر JSON ثم أعد تشغيل السكربت بدلًا من تعديل Markdown المولد.
