### О проекте

Инспектор APK (APK Inspector) — плагин-компаньон файлового менеджера AutoJs6. Коснитесь файла APK, APKS, XAPK, APKM, APKZ или AAB в файловом менеджере — и сразу откроется отчёт проверки: как называется приложение, какая у него версия, какие разрешения оно запрашивает и можно ли установить его на это устройство, всё на одном экране. Пакет никогда не устанавливается, а исходный файл никогда не изменяется.

Отчёт состоит из четырёх разделов: «Сведения о пакете» — имя приложения, значок, имя пакета, версия, диапазон SDK, проверка подписей и цепочка ротации сертификатов, размер файла и контрольная сумма SHA-256; «Компоненты» — каждый split-APK и OBB-ресурс внутри пакета с пометкой частей, подходящих этому устройству (для AAB — список модулей), группировка объявленных в манифесте activity/псевдонимов, service, receiver и provider по количеству и явно заданному состоянию exported, сводка нативных библиотек .so по ABI, размеру без сжатия и совместимости с устройством, а также список стандартных файлов classes*.dex с их размерами без сжатия; «Запрошенные разрешения» — группировка по уровню защиты с выделением опасных разрешений времени выполнения и кратким пояснением; «Безопасность и совместимость» — структурные проблемы и вывод о совместимости с устройством. Кнопка «Открыть manifest» показывает полный отформатированный AndroidManifest.

### Возможности

- Проверка в одно касание: отчёт открывается прямо из файлового менеджера AutoJs6 — без установки, распаковки и доступа к сети.
- Шесть форматов: стандартный APK, контейнерные форматы с несколькими split-APK (APKS, XAPK, APKM, APKZ) и магазинный формат распространения AAB; APKS охватывает экспорт и из bundletool, и из SAI.
- Версия и совместимость: имя пакета, имя и код версии, минимальный/целевой/максимальный SDK — в сравнении с версией Android на устройстве ещё до установки.
- Прозрачность разрешений: группировка по уровню защиты (времени выполнения/опасные, подписи/защищённые и обычные), опасные разрешения показаны первыми с пояснением в одну строку; недоступные уровни остаются видимыми и помечаются.
- Анализ split-APK: перечисляет все APK-записи и OBB-ресурсы контейнера и помечает split-файлы, выбранные для этого устройства (базовый, язык, плотность экрана, ABI).
- Резервное определение приложения по ресурсам: если Android не может напрямую загрузить AAB или слишком большой контейнер, имя приложения и растровый значок для текущего языка и плотности разрешаются из resources.pb AAB либо resources.arsc APK без извлечения всего вложенного APK.
- Экспорт компонентов манифеста: подсчитывает activity/псевдонимы, service, broadcast receiver и content provider в выбранных split-APK или просканированных модулях AAB, группируя явные значения android:exported как экспортировано, не экспортировано или не указано/не определено.
- Обзор нативных библиотек: группирует файлы .so выбранных split-APK или модулей AAB по ABI и размеру без сжатия, отмечая предпочтительный ABI устройства, поддерживаемые резервные ABI и неподдерживаемые архитектуры без извлечения содержимого библиотек.
- Обзор DEX: перечисляет в естественном порядке стандартные файлы classes*.dex выбранных split-APK или модулей AAB с размером без сжатия для каждого файла и в сумме, не извлекая, не декодируя и не декомпилируя содержимое DEX.
- Повторное использование отчёта: удерживайте основную строку сведений о пакете, чтобы скопировать её значение без подписи, либо отправьте точный текст с экрана как `text/plain` через системное меню Android; текст остаётся в памяти, файл и разрешение на хранилище не нужны.
- Проверка подписей и сертификатов: криптографически проверяет схемы APK V2, V3 и V3.1; сообщает о наличии V1; показывает текущие сертификаты и проверенную цепочку ротации с прежними/новыми ролями и отпечатками SHA-256.
- Проверка файлов V4/V4.1: AutoJs6 формирует только точное соседнее имя `<имя APK>.idsig` и выдаёт ограниченный дескриптор только для чтения; плагин проверяет подписанные данные, сертификат и открытый ключ, соответствующий дайджест APK V2/V3, корень fs-verity, встроенное дерево Меркла и подписанта ротации V3.1.
- Читаемые манифесты: двоичные манифесты APK и protobuf-манифесты AAB декодируются в читаемый XML и открываются в отдельном просмотрщике только для чтения.
- Контроль целостности: SHA-256 вычисляется во время чтения файла — можно сразу сверить с официально опубликованными контрольными суммами.
- Структурная диагностика: находит отсутствие базового APK, дубликаты или неразрешённые зависимости split-файлов, несовпадения версий и имён пакетов, помечая каждую находку как блокирующую [!] или информационную [i].

### Как пользоваться

1. Скачайте и установите Инспектор APK, затем включите его в центре плагинов AutoJs6 (требуется AutoJs6 с кодом версии 5277 или новее).
2. Откройте файловый менеджер AutoJs6 и найдите нужный файл пакета (APK, APKS, XAPK, APKM, APKZ или AAB).
3. Коснитесь файла или выберите в его меню «Проверить пакет Android» — через мгновение появится отчёт проверки.
4. Просмотрите отчёт сверху вниз: значок и имя приложения, сведения о пакете, компоненты, запрошенные разрешения, безопасность и совместимость.
5. Удерживайте строку в разделе «Сведения о пакете», чтобы скопировать значение, или нажмите «Поделиться отчётом» на панели, чтобы отправить точный текст с экрана через системное меню Android.
6. Нажмите «Открыть manifest», чтобы прочитать полный AndroidManifest, затем вернитесь назад в файловый менеджер.

> Другие приложения тоже могут передать пакет Инспектору APK через системное «Открыть с помощью» (ACTION_VIEW) — при условии, что используют content-URI с выделенным MIME-типом пакета Android. Плагин работает строго в режиме чтения и не содержит никакой точки входа для установки.

### Поддерживаемые форматы

Основное действие файлового менеджера срабатывает при точном совпадении со следующими расширениями (без учёта регистра):

```text
APK, APKS, XAPK, APKM, APKZ, AAB
```

APKS, XAPK, APKM и APKZ — контейнерные форматы, объединяющие несколько split-APK; AAB — формат App Bundle для магазинов приложений: его можно просмотреть здесь, но перед установкой его нужно преобразовать инструментом вроде bundletool.

### Вопросы и ответы

#### Может ли этот плагин устанавливать APK?

Нет, и это сделано намеренно. Плагин не запрашивает разрешение на установку, и в интерфейсе нет ни одной кнопки установки; его задача — показать содержимое пакета до установки. Установка остаётся за системным установщиком или собственным процессом хоста.

#### Почему некоторые файлы не удаётся проверить?

Частые причины: файл превышает лимит 4 GiB; в кэше устройства мало места (свободными должны оставаться не менее 128 MiB); контейнер превышает пределы разбора по числу или размеру записей; файл был изменён другим приложением во время чтения; либо файл структурно повреждён. Сообщение об ошибке указывает конкретную причину.

#### Доказывает ли проверка подписи, что пакет безопасен?

Нет. Плагин криптографически проверяет целостность и доказательства подписанта для V2, V3, V3.1, V4 и V4.1 и показывает отпечатки и цепочку ротации; но действительная подпись доказывает лишь, что пакет не менялся после подписания, а не надёжность подписанта или приложения. Сверяйте отпечаток и SHA-256 с официальным источником.

#### Почему для AAB-файлов пишут, что они «требуют преобразования перед установкой»?

AAB — формат распространения для магазинов приложений; устройство Android не может установить его напрямую. Плагин декодирует protobuf-манифест и структуру модулей, а также разрешает из resources.pb локализованное имя приложения и растровый значок подходящей плотности, но для установки файл по-прежнему нужно преобразовать в APK(S) инструментом вроде bundletool.

### Разрешения и безопасность

Плагин не запрашивает разрешений на хранилище, сеть или установку пакетов. Выбранный пакет доступен только через временный content-URI только для чтения, выданный хостом; необязательный `.idsig` доступен лишь через ограниченный дескриптор хоста для точного соседнего имени `<имя APK>.idsig`, без перечисления каталога и произвольных соседних путей. Перед проверкой оба входа копируются в снимки только для чтения в закрытом кэше приложения (SHA-256 вычисляется при копировании пакета), и весь разбор выполняется на снимках; `.idsig` ограничен 40 MiB, устаревшие снимки удаляются в течение 24 часов. Запросы файлового менеджера проверяются по каждому полю: версия протокола, идентификаторы запроса и действия, метаданные цели, версия хоста, форма URI, имя, размер, права только на чтение и Binder сеанса. Запросы «Открыть с помощью» принимаются только с выделенными MIME-типами пакетов; application/zip, application/octet-stream и права на запись, постоянные или префиксные права отклоняются.

Чтобы специально изготовленные файлы не исчерпали ресурсы устройства, разбор ограничен следующими пределами; файлы сверх предела отклоняются с пояснением:

- Один файл — не более 4 GiB; при копировании в кэше должно оставаться не менее 128 MiB свободного места; за одно действие обрабатывается ровно один файл.
- Разбирается не более 16384 записей архива, сканируется не более 512 APK-записей на контейнер, имена записей — не длиннее 1024 символов.
- Заявленный размер записи — не более 4 GiB, заявленный общий размер — не более 8 GiB.
- Сканирование манифестов вложенных APK ограничено 256 MiB, метаданные контейнера — 1 MiB, временный APK для загрузки значка и имени — 512 MiB.
- Резервное чтение ресурсов ограничено 32 MiB на таблицу и 4 MiB на значок; поиск таблицы и значка во вложенном APK использует общий бюджет 512 MiB. Превышение, повреждённый ресурс или неразрешённая ссылка отключают только это резервное чтение и явно помечаются.
- Классификация сканирует не более 2048 запросов, показывает до 512 безопасных уникальных имён и ограничивает каждое загруженное пояснение 240 символами; пропуски и недоступные уровни явно помечаются.
- Статистика компонентов сканирует не более 4096 объявлений на манифест и не более 128 манифестов модулей AAB при общем бюджете ввода 16 MiB; пропуски, неопределённые значения exported и сбои отдельных манифестов явно помечаются.
- Нативная статистика сохраняет не более 4096 записей .so и показывает 64 каталогов ABI. Читается не более 512 выбранных вложенных APK при общем бюджете 256 MiB, а центральный каталог каждого APK ограничен 8 MiB; превышения и сбои дают явно помеченные частичные результаты.
- Статистика DEX учитывает все просканированные стандартные записи, но показывает не более 128 путей в естественном порядке; она использует тот же ограниченный проход центрального каталога, что и обзор нативных библиотек, поэтому содержимое DEX не извлекается, не декодируется и не декомпилируется.

### Интерфейс плагина

Хост (AutoJs6) обнаруживает и вызывает плагин по следующим идентификаторам; они приведены для разработчиков плагинов и хостов:

```text
service action: org.autojs.plugin.EXPLORER_ACTION
execute action: org.autojs.plugin.EXPLORER_ACTION_EXECUTE
plugin id: apk-inspector
engine: explorer-action
variant: default
Explorer action id: inspect-android-package
MIME type: Explorer: extension-only; ACTION_VIEW: dedicated Android package MIME types
required host build: 5277
```

Текущая версия выполняет только проверку в режиме чтения: нет кнопки установки, разрешения на установку и установщика пакетов, исходный файл не изменяется, каталоги не перечисляются. V4 использует только точно сформированный хостом кандидат `.idsig`, копирует его ограниченный дескриптор только для чтения в закрытый снимок и сразу после этого закрывает сеанс хоста. Если плагин отсутствует или отключён, хост незаметно возвращается к своему действию по умолчанию.

### Сборка

```powershell
.\gradlew.bat :app:assembleDebug
```

Release-сборка:

```powershell
.\gradlew.bat :app:assembleRelease
```

Параметры сборки и подписи задаются в version.properties и sign.properties; текущий минимум — Android 7.0 (SDK 24), целевой SDK — 36.

Файлы README и CHANGELOG генерируются скриптом .python/generate_markdown.py из JSON-источников и шаблонов в каталогах .readme/ и .changelog/ (10 языков). Чтобы изменить документацию, правьте JSON-источники и запускайте скрипт заново, а не редактируйте сгенерированный Markdown.
